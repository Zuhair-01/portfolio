Laya Windows

The open-source, self-hosted decision engine for Windows. Typed, non-generative AI decisions — choice, score, noul — in a single forward pass, with calibrated probabilities and zero hallucination risk, ported off macOS-only Core ML onto ONNX Runtime and DirectML.

PythonONNX RuntimeDirectMLApache-2.0Arabic + 10 languages
View on GitHub

01Why this exists

The original Laya port for Apple Silicon runs on the Neural Engine, which means macOS only. Most of the world, and most of my own stack, runs Windows. So the same idea was ported onto ONNX Runtime and DirectML, Microsoft's cross-vendor GPU inference stack, where it runs on any DirectX 12 GPU: NVIDIA, AMD, Intel, integrated, with no CUDA requirement.

It also ships a first-class Arabic demo and evaluation suite that the original project does not have.

02What the model actually does

Laya evaluates typed questions — choice, score, noul — over text or JSON state in a single forward pass. There is no autoregressive decoding and nothing to parse. You get calibrated probabilities back, not a wall of generated text.

That is the point of the whole project. A decision system that cannot hallucinate is a different kind of component than a chatbot: it can sit in a pipeline where a wrong sentence would be expensive, because it can only return a typed answer with a probability attached.

03The port

source model      -> Laya typed-decision model (open weights)
Core ML path     -> macOS / Apple Silicon only, Neural Engine
this port        -> ONNX Runtime + DirectML, any DX12 GPU on Windows 10/11

export   onnx_export.py   model -> ONNX
package  quantize.py      optional weight quantisation
run      laya_windows/    DirectML execution path
verify   bench/eval_set.json + bench/run_eval.py   evaluation set
docs     docs/results.json  measured outputs

04Engineering decisions

DirectML, not CUDA. Targeting the widest possible GPU base mattered more than squeezing the last percent out of NVIDIA hardware. A decision engine that runs on the machine in front of you is worth more than one that runs 20 percent faster on a card most people do not own.

An evaluation set in the repo. The Arabic suite and the measured results are part of the project, not a separate paper. A port without an evaluation set is just a claim that it still works.

05Open source, in ten languages

The repository is Apache-2.0 and open-weight, with documentation in Arabic, Chinese, Spanish, Portuguese, Hindi, Russian, Japanese, German, French and Korean, plus a continuous integration workflow and a contributor guide. The Arabic README is the primary one, not an afterthought translation.

Translation was treated as part of the port rather than a follow-up task, because the users this port exists for are not on the Apple platform.

06Limitations

  • It is a decision engine, not a text model. It will not write your email. If you need generation, this is the wrong tool.
  • Typed decisions need typed inputs. Free-form text has to be structured first.
  • Quantised variants trade a small amount of calibration accuracy for memory, and the exact trade-off depends on the model and the hardware.
