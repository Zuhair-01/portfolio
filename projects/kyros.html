Kyros

The dispatcher that decides which AI model is allowed to touch a task, and the mutex that stops your GPU from becoming the bottleneck when more than one of them tries. Every decision comes with its reason attached, in one line, with no black box in the loop.

Python 3.11+Zero dependenciesMIT16/16 tests
View on GitHub

01Problem

Send every task to the biggest model and you burn budget on work a cheap model could have handled. Send everything to the cheapest model and you get silent failures exactly where judgment mattered most: auth, money, migrations.

And separately: if more than one local AI process tries to load onto a single consumer GPU at once, one of them crashes or degrades to system RAM and becomes unusably slow. A process that dies mid-run can also leave a lock file behind forever if nothing checks whether the holder is still alive.

02Solution

kyros.router classifies a task by size, risk and whether an existing pattern exists to imitate, then returns a tier: cheap local model, low-cost cloud, mid-tier cloud, frontier cloud, or retain, a signal that the task needs human or senior judgment and should not be dispatched at all.

kyros.escalation tracks per-task failure history, so a model that fails twice on the same task stops being retried automatically instead of looping. kyros.gpu_lock is a file-based mutex keyed by PID that grants exclusive GPU access to one process at a time and auto-clears a lock left by a process that has since died.

03Architecture

Task (concern, output size, files touched, risk tags, context size)
        |
        v
kyros.router.route()
  - high-risk tags (auth/money/migration/concurrency/security) -> RETAIN, always
  - cross-file diff too small to verify mechanically           -> RETAIN
  - bulky + single-file + pattern exists + fits local context  -> LOCAL
  - small + fully-specified                                    -> CLOUD_LOW
  - standard feature-sized                                     -> CLOUD_MEDIUM
  - large / unbounded scope                                    -> CLOUD_HIGH
        |
        v
kyros.escalation.EscalationLadder
  - records pass/fail per task id
  - 2 failures on one task -> should_retain() flips true, stop re-dispatching

kyros.gpu_lock.GPULock  (independent, used by whichever process loads a model)
  - acquire(owner, pid): refused if held, or if free VRAM < threshold
  - a lock whose owning pid is no longer a live process is cleared automatically
  - release(pid): only the holder's own pid may release

04Technical decisions

No LLM in the decision loop. The routing policy is a pure function over task metadata, so the same task always routes the same way and every cutoff is unit-tested. A model that decides which model to use is a failure waiting to happen.

Risk overrides size. Auth, money, migrations, concurrency and security-tagged tasks are always retained at the highest tier regardless of size, closing the failure mode where a cheap model quietly gets handed something expensive to get wrong.

Crash safety from the OS, not from a file. Lock liveness is checked against the real process list, not just the presence of a lock file, so a crashed holder cannot permanently starve every other process of the GPU.

Zero dependencies on purpose. The whole package is Python standard library. No network calls, no API keys, nothing to configure before the test suite runs.

05Not a simulation

gpu_lock.py is the same coordination primitive running in production today across concurrent local-AI workloads that share one 8 GB GPU: a video-clipping pipeline, a local LLM and a vision model all draw from the same card, and none of them may load without acquiring this lock first.

The routing policy is documented separately in docs/routing-policy.md, with each cutoff tied to the failure case it exists to prevent.

06Verification

  • 16/16 tests passing, re-run locally on 2026-10-29 with python -m pytest -q (4.74 s), covering every routing branch, the two-strike escalation rule, and five GPU-mutex crash and contention scenarios.
  • Every routing cutoff is unit-tested against a real failure case, not against the happy path.
  • Licence MIT. The package is pure standard library, so the test suite runs on a clean machine with nothing installed.
Verified, not claimed: the 16 tests were executed on 2026-10-29 for this case study, not copied from an earlier note.

07Limitations

  • Task metadata is supplied by the caller. Kyros routes what it is told about; it does not read the repository to discover scope.
  • VRAM thresholds are heuristic and hardware-dependent; the mutex serialises access, it does not schedule across GPUs.
  • The tier names assume a cloud-provider ladder. Adapting them to a different provider set means editing the policy document and the tests with it.
